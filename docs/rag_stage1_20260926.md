# 公开项目资料问答第一阶段

本阶段增加独立的两步式 RAG 试验入口，回答关于**本项目已公开方法、类别说明和评测边界**的问题。它不判断当前道路图片，不提供交通法规条款或驾驶建议；原有四类 YAML 工具 `lookup_sign` 保持原样。

## 实现与边界

- 只读取仓库公开的 `README.md`、`docs/direction_upgrade_v3.md` 和 `knowledge/signs.yaml`，形成 45 段带文件路径、起始行和稳定编号的检索资料。没有读取团队内部标注 DOCX、原始道路图片、`.runtime` 或 `outputs`。
- 用中文字符二元/三元片段、英文词和类别别名做 BM25 排序。离线模式展示原文摘录；DeepSeek 模式只发送问题与命中的公开文字段落，要求引用编号。没有 embedding、FAISS 或其他向量数据库。
- 有明显当前图片指代的问题直接拒绝交给文档检索。若模型没有给出有效引用编号，也拒绝返回其生成文字。这个格式检查**不等于事实核查**。
- 页面提供独立知识问答区及检索来源；接口为 `/ask_knowledge`，不影响既有图片问答和方向解析入口。

## 当前验证

开发者自写的 28 道问题在 `knowledge/rag_eval.development.json`：20 道有答案题 Top-3 命中预期主题 **20/20**；8 道无答案题正确拒绝 **7/8**。失败题“项目的正式车规认证编号是什么？”因“编号”等普通字词召回了不相关段落。问题和规则已用于开发调试，标记为 `development_only`，未经独立人审，不能当作泛化性能。

真实 DeepSeek 三题联调：关于冻结测试和图片像素传输的两题均返回与公开段落一致的带编号回答；车规认证编号题返回资料不足。图片没有发送。`outputs/rag_live_verification.json` 保存本机记录，不公开 API 密钥或内部文档。

项目原有 **131 项自动测试通过**。本地页面返回 200，`/ask_knowledge` 对有依据问题返回段落和来源，对当前图片内容问题拒绝。这只验证接口链路，不等于独立用户评测或新机器安装验证。

## 尚未达成

1. **无答案识别不稳。** 当前离线检索仍可能返回主题表面相似、实际不能回答的段落；真实 LLM 虽在这次车规题正确拒答，不能据此声称普遍可靠。下一阶段应独立编写更多无答案和混淆题，并做人审。
2. **语义检索未实现。** 目前是词法检索；应在固定题集上比较本地中文 embedding 与 BM25 的命中率、误召回、CPU 耗时。只有实测提升才引入额外依赖。
3. **引用不是事实验证。** 目前只核对编号属于检索结果，未逐句核对回答是否被来源支持，也没有来源版本更新审计。
4. **不是图文联合 RAG。** 文档问答没有接收 YOLO/OCR 的图像证据，也不会根据知识库推断当前图片的具体路牌、地名或箭头。
5. **资料范围有限。** 只覆盖项目公开说明和四类粗粒度语义；团队内部标注手册和国家标准均未纳入公开语料。

下一阶段优先做独立问答集、答案依据复核及语义检索对照；辅助标注和清洗 Agent、干净环境复现仍是计划，尚未开发。
