## 指路牌解析（进行中，未达可用水平）

目标：从 `point-l`（class 2，含文字的指路标志）牌面读出地名与方向箭头，建立“地名 ↔ 方向”对应。当前**只有文字层可用**，方向关联层未达标。

已完成并验证：

- 样本筛选：扫私有数据集 10,230 个标注文件，2,058 个满足 class 2 占比 ≥0.6，裁出 64 张牌面（`scripts/extract_sign_crops.py`，原图分辨率）。注意：数据集的 `images/<batch>/` 是空目录，原图实际在 `train/images`、`test/images`。
- 文字识别：RapidOCR（onnxruntime）在 64 块牌面上 0 失败，平均 1.39 s/块，返回四点旋转框（`outputs/ocr_batch.json`）。已知错误：「迎宾路」→「迎宾务」、「翠园路」→「弹性道路」，案内板/水印文字会混入。
- 环境坑：onnxruntime 1.30.0 在本机导入即崩（0xC0000005），已验证 1.18.1 + protobuf 4.25.3 可用。
- 关键判据发现：夜间牌面白字在照片里是**蓝白**（B≫G≈R，饱和度高于蓝底），灰度中位数甚至低于背景（27 vs 57）。因此按亮度或饱和度的全局阈值都会漏掉文字，唯一可用判据是**局部对比度**（自适应阈值）。
- 评测集：20 块牌面的人工判读 ground truth（`scripts/eval_ground_truth.py`），覆盖清晰白天、复杂路网图、车道图、分叉图与 5 块应拒答的负样本（无箭头的距离牌/海拔牌/路名牌/高速编号牌/单位提示牌）。

评测结果（`scripts/evaluate_sign_parser.py`，报告 `outputs/sign_parse_eval.json`）：

| 指标 | 数值 |
| --- | ---: |
| 文字召回（地名被 OCR 命中） | 1.00 |
| 已关联方向正确率 | 0.50 |
| 关联严格正确率（同名且方向一致 / 全部可判定 route） | 0.333 |
| 关联覆盖率 | 0.667 |
| 歧义或应拒答地名被强行给出方向 | 17 / 61 |

已试并**失败**的箭头检测方法：连通域几何法（汉字笔画混入，08342 报 8 个）、合成箭头模板多尺度匹配（二值 NCC 局部高分，08419 报 216 个）、PCA 尖端方向分类（对真箭头只给 0.15–0.30 置信度）。有效的一步是**用 OCR 文字框遮罩文字**后再找前景，候选从 969 降到个位数；进一步收窄到“文字组邻域 + 尺度匹配”后方向正确率由 0.375 升到 0.50，过度断言由 20 降到 17。

结论：**文字层可用，箭头层不可用**。牌面上箭头与外框、分隔线、图标、路网示意在几何上高度相似，靠硬编码阈值无法稳定区分；且当前对“没有箭头的牌”仍会强行给出方向（17/61），这是不可接受的错误类型。

### 方向调整：改为“读文字 + 推断意图”（2026-09-16）

鉴于 point-l 中包含大量非地名提示牌，且箭头关联层不可用，改为只做两件事：读全牌面文字、由语言模型推断该牌想表达什么。已实现并验证：

- 新增工具 `read_sign_text`（`traffic_agent/sign_text.py`）：检测 point-l → **原图分辨率裁剪** → 可读性判断 → OCR，逐段返回文字、置信度与四点坐标。26 项 unittest 通过。
- 可读性门槛（新增）：夜间样例检出的牌面裁剪仅 75×118、144×274 像素，肉眼无法辨认，OCR 必然为空。低于 160 px 时明确报告“不具备可读条件”，避免上层把“OCR 无输出”误读为“牌面无文字”。真实联调中模型据此回答“文字为空只表示本次 OCR 未识别出内容，不能据此判断牌面上不存在文字”。
- 真实高分辨率牌面 + DeepSeek 意图推断（`scripts/verify_sign_intent.py --live-llm`，报告 `outputs/sign_intent_verification.json`）：
  - `08342_2`（平安路 / Pingan Rd /（迎宾务））：逐段复述原文，推测为指路标志，并指出「迎宾务」语义不完整、意图不确定；
  - `08845_1`（翠园路 / 弹性道路）：推测为路名指示，明确标注为推测并给出依据文字；
  - `08303_1`（龙游路西段等 5 组路名）：推测为路口方向地名指示，并主动声明“OCR 只给出文字内容，未给出各段文字在牌面上的方位排布，因此无法判断哪条路对应哪个方向”。
- 离线规则模式只返回 OCR 原文并声明“未做含义推断”，不假装能推断。

结论（本次方向）：**“读文字 + 推测意图”这条线可用且诚实**；“文字→方向”关联仍是未解决能力，被明确排除在对外口径之外。

### 提示/规则类标语牌的样本覆盖（2026-09-16）

目标：扩大“行车规范/施工提示”这类**非地名提示牌**的覆盖，并量化分类器表现。

- 抽样规模：裁出 860 张牌面（约 430 个标注 id，按尺寸分层），对其中的 541 张跑 OCR 并分类；另用 `--start 400` 取 241 张作**留出集**（不在调词样本内）。工具：`scripts/collect_prompt_signs.py`，报告 `outputs/prompt_sign_candidates.json`、`outputs/prompt_holdout.json`。
- 产出率：`point-l` 候选中提示/规则类约占 **2%**（541 张中 10 张，241 张中 5 张），其余为地名指路类（约 64%）与编号/距离/单位/待判（约 34%）。**结论：该数据集里“施工/规范类标语牌”本就稀少，且它们多以“请按导向车道行驶”这类短句出现在指路牌上，而非独立大牌。**
- 分类器（`classify_text`）分级：prompt（对驾驶员的行为要求）/ info（设施服务告知）/ place（地名）/ code / other。评测集 57 条人工判读（`scripts/prompt_text_gold.py`，含 10 条留出集样本），结果见 `outputs/prompt_classifier_eval.json`：

| 类别 | 条数 | 精确率 | 召回率 |
| --- | ---: | ---: | ---: |
| prompt（行为要求） | 19 | 1.00 | 0.947 |
| info（设施告知） | 8 | 1.00 | 1.00 |
| place（地名） | 7 | 1.00 | 1.00 |
| 整体准确率 | 57 | — | 0.982 |

- 留出集暴露并修掉的问题：单用“车辆/行车/车道”等泛指词会把 **“车辆管理分所”（单位名）** 和 **“公路自行车赛场”（赛事标识）** 误判为提示语。改为“强标记（请按/禁止/严禁/各行其道…）单独成立，泛指词需与强标记同现”后，精确率回到 1.00。
- 端到端验证（`scripts/verify_prompt_signs.py`，报告 `outputs/prompt_signs_verification.json`）：8 块真实提示牌中 **5 块成功抽出期望文字**（请按规定车道行驶、各行其道/文明驾驶、请选定行车方向、前方路口禁止左转、请选择车道行驶）；另外 3 块裁剪仅 116×67 / 101×61 / 200×99 像素，被**正确标记为“不具备可读条件”**而非漏检。
- 可读性门槛据实测调整为 128 px：144 px 的提示牌（08325）仍可识别，而 61–67 px 的牌面 OCR 已无输出。

**发现的严重数据问题（已修复）**：本数据集不同批次目录存在**重复 id 且为不同图片**。此前裁剪文件仅用 `{id}_{序号}` 命名，导致不同图片的同名文件互相覆盖，出现“同 id 却读到另一块牌”的串号（6 个案例中 4 个受影响）。现已改为 `{批次}_{id}_{序号}.jpg`（`scripts/extract_sign_crops.py`），并重建全部裁剪；验证脚本也改为按“id + 期望文字”定位裁剪。此项对后续任何按 id 关联图片/标注的工作都成立，需特别注意。

### 提示牌意图推断实测（2026-09-16，真实 DeepSeek）

脚本 `scripts/verify_prompt_intent.py`，问句固定为“这块牌想表达什么？”，样本按抽样报告的 `prompt_like` 程序化选取（按**裁剪路径**去重，避免重复 id 串号），报告 `outputs/prompt_intent_verification.json`。

| 组别 | 样本数 | 通过 | 判据 |
| --- | ---: | ---: | --- |
| 提示/规则类牌面 | 6 | **6** | 判为行车规范/提示类，且标注为推测、引用依据文字、不给驾驶指令 |
| 地名指路类（对照） | 2 | **2** | 不说成对驾驶员的行为要求 |
| 不具备可读条件 | 1 | **1** | 明确拒答，不猜测 |

典型输出：

- `08327`（文字仅「请按规定车道行驶」）→“想表达的是**行车规范类提示**……由于只有这一段文字、没有地名或数字信息，无法进一步判断具体指向哪条车道或哪类车型”。
- `08324`（「请选择车道行驶 / PLEASE DRIVE THE CORRECT WAY」）→“**车道选择类的行车规范提示**，依据是这两段语义一致”；对 OCR 切碎的「儿」「7」明确表示“不成词句，不做含义推断”。
- `08557`（「S50 / 株洲北 清水塘 / 1.5km / 请进入集散车道」）→同时识别出地名距离与「请进入集散车道」提示语；指出「微信公」为水印式残缺文字、无法判断。
- `08321`（含地名）→判为指路标志；把照片水印「想去重庆啦」单独指出“与指路标志常见内容不符，无法确认其在牌面上的含义”。
- `04246`（72×82 像素）→“无法识别……不是‘不确定含义’，而是根本没有可依据的文字内容。按规则，我不能根据检测类别或外观去猜测牌面内容”。

结论：**“读文字 + 推测意图”在提示/规则类牌面上实测可用**，且模型对“文字残缺/水印/不可读”的处理与设计约束一致。

## 尚未验证

- 全数据集精度、GPU 推理、跨平台与干净环境重装、并发压力。
- 语义依据来自团队内部标注说明，**非国标**：四类为粗粒度类别定义，不含细分标志种类（如具体限速值、具体禁令种类）的识别能力。
- 类别语义的边界案例（例如“红白箭头计入 ban”“非三角黄牌计入 wran”）只按标注说明的统计口径记录，未逐条比对原始标注文件抽样核验。
- 上下文压缩只验证了折叠统计正确、注入格式正确与 8 轮联调，未做长会话（数十轮以上）与多图片切换的压力测试。
- 离线规则模式对“摘要”类问题直接返回折叠上下文；DeepSeek 模式下该表述属于自由提问，模型可能选择调用工具，行为不做保证。
- 检索目前是关键词/别名匹配，未验证大规模知识条目下的召回质量，也未引入向量检索。
