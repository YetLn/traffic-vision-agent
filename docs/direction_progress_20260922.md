# 简单指路牌方向解析：2026-09-22 开发记录

## 结论

已实现本地运行的原图检测、OCR、独立箭头形状识别、证据坐标、保守关联、拒答、可视化及评测入口。**尚未实现能稳定使用的端到端“地名—方向”解析，未达到用户提出的验收指标。**

16 张真实道路原图开发压力测试输出 0 条方向关系，10 条可判定目标关系全部未覆盖。准确率为 `null`（无输出），覆盖率为 0%。13 张范围负例没有输出方向，但整个系统没有输出任何关系，这不能证明拒答能力已达标。需要同时改善正例覆盖后再评价负例误报。

## 已交付的功能

- Gradio 新入口“简单指路牌方向解析 · 试验版”，与上方原图和置信度连接。
- 使用现有 YOLOv12 权重，始终从 EXIF 归一化道路原图开始；不使用标注框代替检测。
- 牌面按原图像素裁剪。OCR 保留文本、置信度、四点框；方向模块依据完整箭头形状判断，不依据文字在左/右猜方向。
- 原图坐标输出牌面框、文字框、箭头框、文字与箭头 ID 关联、低质量或不支持原因。
- 证据图：黄框牌面、蓝框文字、紫框箭头；仅已接受的关系画绿色连线。
- 截断文字、边缘箭头、低置信度、显著倾斜、非唯一对应、多列/复杂布局明确拒绝。
- 形状 IoU 与方向分数差只作为几何诊断，不能当作模型正确概率。
- 独立评测器按原图牌框 IoU≥0.5 一对一匹配，按同牌地名+方向严格匹配；漏检计覆盖损失，多检和重复关系计误报；输入错误不覆盖已有报告。
- 修复了 RapidOCR 的 PIL/ndarray 通道顺序不一致问题，增加共享 OCR 推理锁；换图/阈值变动会使在途方向结果过期，防止旧证据回填。

当前关联器仅支持**单列、一行中文地名对应一个独立箭头**。单箭头覆盖多个地名仍是用户目标的一部分，当前尚未实现。没有用 DeepSeek 猜测缺失的视觉证据，整个新入口没有发送图片或调用外部模型。

## 实际数据与开发结果

Private 的 `images` 是空批次目录，真实图像位于 train/val/test 的 images 中，共 10,230 张。原始 labels 下按批次存放完整标注；val/test 的同级 labels 为空，新提取器只在原始标签 stem 唯一时回查。保留有效行，记录一条零宽的 class 1 异常行。

Night 有 4,487 张图，其中 1,405 张增强图本轮排除；216 张带非默认 EXIF 方向的图片先跳过，避免未确认的标注坐标旋转。候选集因此不代表完整海南/夜间分布。

`outputs/direction_dataset_v3` 是当前有效提取版本：

- 2,455 个满足宽高/面积门槛的 class 2 候选框；选取白天和夜间各 120，共 240 个裁剪。
- 240 个唯一 ID、240 个裁剪 SHA 全部核验通过。ID 同时包含源图哈希与框哈希。
- 按同图、近重复图和夜间采集组保守合并成 112 组；**不是 112 个已核实的不同实体**。
- 按面积选取有偏；夜间 120 张集中在 9 个采集组。不能作为代表性随机测试集。
- 名为 `holdout_candidate` 的标签只是候选。已阅览、用于调试的样例及相关组一律视为开发数据；目前没有冻结测试集。
- v1/v2 为排错中间产物，v2 曾有同图不同框 ID 冲突；v3 修复，正式报告只引用 v3。原始数据未修改。

`outputs/direction_review/gold.development.json` 含 16 个由助手目视核对的开发目标牌：3 个正例、10 条关系、13 个范围负例。共享路网/车道图即使人能理解，也按当前范围外处理；其可读关系保存在 reference_relations，不计正例。每张原图只审阅目标牌，未穷举其他所有牌面；尚无实体复核或人工确认的完整文字/箭头框金标。

`outputs/direction_e2e_release` 保存最终原图预测、证据图、权重/代码哈希和评测。原图运行器只把 source_image 交给推理，不把金标框、方向或地名传给算法。

模型存在漏牌、只框中局部文字区和其他类别混淆。08839 的证据图能读出部分文字并定位向上箭头，但 YOLO 框截断了“北京西路”和“白云”，且牌面为多地名共享箭头布局，必须拒绝关系输出。08785 的三分区独立箭头牌在 YOLO 阶段未检出。

几何阶段另做了 10 张开发裁剪诊断（`outputs/direction_geometry_diagnostics.json`）：在新三行牌上找到向上箭头，在旧 08342 两张裁剪上找到左/上箭头；两张旧裁剪属于同一实体且用于调参。其余存在透视、文字框与箭头相交、夜间反光造成的拒绝/漏检。**这些裁剪结果不是端到端成功案例。**

## 下一步应优先解决什么

1. **先修牌面检测**：当前 16 个目标仅2个整牌匹配，直接限制后续覆盖率。检查原训练类别及框定义是否一致，补充完整大型牌面标注；用未参加测试的训练集调整检测模型。做新图多尺度检测时也要从真实原图运行并独立记录增益。
2. **建立实体和证据金标**：按实体/采集组核对、选择30块开发与70块未接触测试（含20负牌），标文字框、箭头框、关系与拒答原因。冻结文件和哈希。现有目视调试组不能再当未见测试；已有YOLO训练数据也不能宣称检测泛化测试。
3. **训练独立箭头检测/分割并校正透视**：当前几何模板是诊断基线，OCR误框、反光和强透视下召回不足。新增任务标注比增加 Agent 框架更直接。
4. **扩充关联到一箭头多地名**：以牌面分区、文字组和箭头证据建立对应；仍不扩展到复杂路网。先在开发集提升覆盖，再用冻结集一次性检验准确率与负牌误报。

在此之前，简历可如实写“实现交通牌面检测与文字/箭头证据可视化、拒答机制和原图评测工具，完成开发集失败分析”；不应写“实现可靠的地名方向解析”或“90%准确率”。

## 工程验证

68 项工程测试通过，包含原图入口、EXIF 坐标、文字/箭头框偏移、形状拒绝、低质量与歧义关联拒绝、评测失败保留报告以及换图后丢弃过期结果。Gradio 测试过程中出现资源释放警告，测试无失败。工程测试数量不表示真实识别准确率。

真实本地页面 `/read_directions` 使用 08839 原图联调，验证 YOLO 入口、证据图返回、坐标范围及截断文字拒答；结果保存于 `outputs/direction_ui_validation.json`。页面当前提供的是未通过语义验收的试验功能。
