# 项目范围与简历口径

本次实现依据用户提供的 DeepSeek DOCX、此前 GPT 方案 Markdown，以及现有简历的目标检测科研背景。材料作为设计参考，示例中的分类名称、成绩和术语不作为已完成事实。

第一版目标是让已有科研权重提供可以演示的视觉工具：上传图片、检测、按原始类别计数、最高置信度查询、可视化、多轮追问。优先完成本地闭环；DeepSeek 工具循环提供可配置入口。

不重训模型，不修改简历原件，不复述参考材料中没有实测依据的 5.3% 提升等数字。科研成果继续属于科研经历，应用能力由这个新项目单独证明。

当前可用于记录项目的描述：

> 将已有昼夜交通标志 YOLOv12 权重封装为结构化视觉工具，搭建 Gradio 本地查询界面，实现类别统计、置信度查询和检测结果可视化；设计会话级检测缓存、换图失效、工具调用轨迹、上下文折叠机制与标志语义知识库查询工具。

在真实 DeepSeek API 联调完成后再加入：

> 接入 DeepSeek Function Calling，由语言模型选择视觉工具并基于执行结果回答；实现工具参数校验、调用轮数上限、会话上下文折叠（结构化统计折叠，非 LLM 语义摘要）与标志语义知识库查询（依据项目标注说明，无依据时明确拒答）。

不应写入未实现的自进化、工业级部署或未实测的准确率/延迟提升。术语口径：
- 上下文压缩只能表述为“确定性结构化折叠”，不能写成 LLM 语义摘要或 Chain-of-Thought 压缩。
- 原有标志类别工具 `lookup_sign` 是**四类 YAML 的关键词/别名检索**，未使用向量库。2026-09-26 另增公开项目资料的两步式 RAG 试验：BM25 检索段落 → DeepSeek 引用回答；目前只有开发题集和少量真实 API 联调，不可声称向量检索或独立测试通过。
- 语义依据是团队内部标注说明《labels instruction.docx》，**不是国标**：简历与文档均不得声称依据 GB 5768 等国家标准。
- 四类为粗粒度类别（警告/禁止/指路/指示），不得声称能识别限速数值、具体禁令种类或判断行车安全。
- 指路牌部分只能写“识别牌面文字并推断该牌想表达什么”，**不得写“解析地名与方向箭头的对应关系”**：评测中方向关联严格正确率仅 0.333，且对无箭头牌面会误给方向。意图推断必须表述为“模型推测”，并说明依据文字。

离线规则模式与 LLM 工具调用模式需在演示时明确区分。
